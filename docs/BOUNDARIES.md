# FolioChest / 资料匣 边界与安全说明

配套文档：[项目设计](DESIGN.md)、[文件格式](FORMAT.md)、[安全策略](../SECURITY.md)。

本文集中记录信任边界、一致性不变量与已知限制。当前项目仍为原型，仅使用合成数据测试，尚未经过独立安全审计。

## 1. 信任边界

### 1.1 保护目标与明文范围

- **密文保护**：`value` 与附件在磁盘及同步传输中始终以 AES-256-GCM 密文保存。
- **明确公开的元信息**：`key`、`description`、`group`、条目版本元信息、文件数量与大小保持明文。不要在这些字段中填入密码、Token、恢复码或私钥。

### 1.2 受信任范围与不做出的保证

- 受信任部分包括本机操作系统、本地运行进程、已配对的 harness 以及用户主动启用的系统凭据服务。
- 无法抵御已控制操作系统、当前用户会话或进程内存的攻击者。
- 已返回给 AI 客户端的明文无法通过撤销授权或锁库收回（客户端可能缓存或发往云端模型）。
- Go GC 与浏览器运行时限制了内存即时彻底擦除的能力。
- 加密与外部同步均不代替独立加密备份。

## 2. 认证、设备与锁定

### 2.1 主密码与变更

- Argon2id 仅用于解开 `vault.json` 中的 32 字节随机库密钥；不把主密码提供给 AI、命令行参数或日志。
- **变更主密码**仅使用新 salt/nonce 重新包装同一个库密钥，完成后锁定并清除会话、审批与本机设备授权。它**不是数据密钥轮换**，旧备份和已复制的库密钥仍能解密原有记录。

### 2.2 本机设备凭据与浏览器记忆

- 开启“服务启动时自动解锁”需已认证网页、CSRF 校验及再次验证主密码；库密钥只存入 OS 凭据库（Windows Credential Manager / Linux Secret Service `default` 或 `login` 集合），不回退为普通明文文件。
- 凭据绑定 `vault_id`、`vault.json` 完整字节 SHA-256 及规范化目录路径；进程启动时只尝试一次，手动/空闲/系统锁屏后不自动重开。
- 停用设备授权时先将禁用标记落盘并撤销浏览器记忆，再尝试删除系统凭据；清理失败会保留待清理标记提示重试。
- “记住这个浏览器”独立配置，颁发 90 天随机 `HttpOnly` / `SameSite=Strict` Cookie（服务端仅存 SHA-256 哈希），仅在当前解锁代次有效，新授权替换旧记忆。
- 本机配置目录不得位于资料库目录内（含符号链接嵌套）。

### 2.3 自启动与单实例启动器

- 用户级自启动（Linux XDG Autostart / Windows `HKCU\...\Run`）仅记录固定程序路径、`--device-dir`、`--listen` 与 `--background`，不含密码或资料库路径；拒绝临时 `go run` 路径及平台非法转义字符（如 Linux 路径中的 `$`、`` ` ``、`\`、`=`）。
- 同一 `--device-dir` 通过 `launcher.lock` 文件锁保证单实例，重复启动通过 `launcher.json` 中的私有启动凭据验证回环 HTTP 实例后再打开浏览器。

### 2.4 锁定策略

- **空闲锁定**（0–1440 分钟，默认关闭）：仅由已解锁网页的用户操作续期，后台轮询和 MCP 调用不续期。
- **系统事件锁定**（默认开启，与空闲锁定独立）：Linux 通过本地系统 D-Bus 监听 `systemd-logind`（核对当前用户图形会话及信号真实 owner）；Windows 监听当前会话 WTS 与电源通知。
- 请求入口与两秒心跳检查墙上时钟跳变（停顿超过 15 秒或回拨超过 5 秒即锁定）；审批、网页会话与空闲期限同时比较单调时钟与墙上时钟（取先到期者），防止系统挂起延长有效期。
- 监测中断时锁定一次；持续不可用时允许用户明确输入主密码解锁并显示保护受限提示，但已知系统仍处于锁定/休眠状态时拒绝解锁。

## 3. MCP 授权与网页操作隔离

- 客户端凭据（`clients.json` 仅存哈希）、资料库解锁状态、key 三态策略与单次审批属于独立层级；`allow` 仍要求资料库已解锁且客户端有效。
- `deny` 策略直接拒绝，不能通过审批绕过；`discover_entries` 仅返回非删除条目的公开元信息，不返回正文或摘要片段。
- 禁止将模型参数、正文或 `description` 中的指令当作用户批准。单次批准绑定客户端、会话、key、操作范围、内容摘要与版本，且仅可消费一次。
- 读取与修改权限严格隔离：允许修改不暴露旧值；没有读取权限时，冲突或错误不回显密文/旧明文；历史恢复、删除、重命名、分组管理、正文搜索、备份、改密码、格式升级与目录选择器**仅向已认证网页开放**，不接受 MCP Bearer 凭据。

## 4. 本地网页安全

- 服务仅监听回环地址，校验 `Host`、`Origin`、`Sec-Fetch-Site` 及 `X-FolioChest-CSRF`（JSON 请求体）；不配置开放 CORS。
- 文档响应禁用缓存，使用每页随机 192-bit style nonce 配合严格 CSP（脚本仅同源，无 `unsafe-inline` / `unsafe-eval`）。
- Markdown 渲染禁用原生 HTML，拦截危险 URL，并将图片替换为转义说明，不自动请求外部资源。
- 系统文件夹选择器由显式网页 POST 请求触发，单实例仅允许一个选择窗口（90 秒超时），锁定、切库或会话变更时自动取消并丢弃晚到结果。

## 5. 外部同步、格式升级与恢复边界

- **外部写入容错**：每次保存均先校验当前 `vault.json` 与依赖完整性；读取文件使用 `Lstat` 禁符号链接与限长读取，写入采用同目录临时文件 + fsync + 原子替换（不使用先删后改回退）。
- **缺失与冲突**：同一批次所有变更的父版本依赖均齐备后才生效；运行期已观察到的 head（含删除/改名/分组移动）若因同步回滚消失，会在当前内存中保持 `missing` 状态而不回退读取祖先版本（注意：重启或锁库后内存观察状态会重置）。并发分支保留所有 head，合并与全分支删除要求绑定完整 head 集合并逐项取更严格权限。
- **删除与重命名（格式 2+）**：删除仅追加认证墓碑记录，不擦除历史或释放空间；回收站仍占用原 key，普通写入不得借用已删除名称新建条目。
- **独立空组（本机元数据）**：空组名称记录在设备配置目录 `group-catalogs/`，按资料库 ID 和路径隔离，最多 512 个；属于明文组织信息，不携带正文、凭据或授权。新建/编辑仅接受已认证网页请求，锁库或切库后拒绝旧代次写入。条目所属组仍以认证记录为准，本机目录不能覆盖成员关系或授予权限。此目录不随资料库同步，也不包含在 ZIP 备份中；资料操作成功而本机目录保存失败时明确报错并要求重新读取，不承诺跨两类文件的原子事务。
- **单层分组（格式 3）**：全组重命名/解除绑定完整当前成员（含回收站），单批上限 20 条 / 8 MiB，不静默拆批。
- **显式格式升级**：格式 1/2 不会在普通打开或改密码时静默升级。升级格式 3 要求验证主密码、`confirmed: true` 及 `target_format: 3`，完成后锁定并停用本机设备授权。由于同步无跨设备原子性，升级前必须先停用并更新所有旧程序。
- **备份与恢复**：ZIP 备份保留原密文与明文元信息（不二次加密容器）；恢复先在隔离目录校验密码、认证标签、路径安全与父版本依赖，仅写入新目录或空目录，不覆盖现有数据，也不恢复设备凭据。
- **兼容标识保留**：`keyfolio/*/v1` 加密域、凭据命名空间 `io.github.shenjiecode.keyfolio`、默认配置目录 `keyfolio/`、Cookie 及旧启动项标识在品牌更名后保持不变，避免破坏既有资料库和本机状态。
