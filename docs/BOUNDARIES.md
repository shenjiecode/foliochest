# Keyfolio 边界与安全说明

- 状态：实现约束与待验证清单；能力是否完成以实际代码及测试为准。
- 整理日期：2026-11-25。
- 配套文档：[项目设计](DESIGN.md)。

本文件集中记录信任边界、异常处理、数据保护与验收要求。实现时须同时遵循主设计的功能语义；这里不代表已经通过安全审计或具备任何认证。

## 1. 产品与信任边界

### 1.1 保护目标

- 文件被复制或同步到第三方存储后，value 与附件仍以密文保存。
- AI 只能通过获准的请求读取或替换目标内容。
- 运行期间出现外部文件变化时，不静默覆盖用户工作，不把不完整文件当有效版本。
- 用户能够利用主密码、完整资料库及有文档的恢复工具恢复数据。

key 和 description 保持明文，并作为 AI 优先读取的元信息。账号、项目、服务名称及用途说明可能因此暴露；两者应只写用于定位的描述，不填写密码、恢复码、Token 或私钥。文件数量、大小和修改活动也不在当前隐藏目标内。

### 1.2 受信任部分

- 本机操作系统、正在运行的程序及其更新来源。
- 解锁期间持有密钥的本地后台。
- 经配对、负责展示真实用户确认的 harness 及适配层。
- 用户选择保存自动解锁凭据时所依赖的系统凭据服务。

外部同步工具不负责授权或解密。即使传输的是密文，同步工具仍可能造成覆盖、删除、旧版本回传或不完整到达，应用需要按数据状态处理。

### 1.3 不作出的保证

- 无法凭 MCP 权限抵御已经控制操作系统、进程内存或程序文件的攻击者。
- 具有任意命令执行、调试或修改程序能力的 Agent，不会因为接入了 MCP 就自动被隔离。需要更强隔离时，另行设计系统权限与沙箱。
- 已发送给 AI 的明文无法通过撤销授权收回。
- 外部文件同步不能提供天然的全设备实时一致性。
- 加密不代替备份，也不自动隐藏元数据。

## 2. 登录、设备与自动解锁

### 2.1 一个主密码

主密码用于解锁资料库的密钥体系。具体密码派生、包装密钥和内容加密方式待确定，采用成熟密码库和有文档的格式。

- 不把主密码发给 AI 或写入 MCP 参数、聊天、命令行参数、日志。
- 不向 AI 提供由主密码派生的子密码作为部分授权手段。
- 不使用直接对低熵主密码做 HMAC 等简单方式替代抗离线猜测的密码派生。
- 不自创加密算法；算法、随机数、nonce、认证范围和附件分块协议须一起评审。
- 主密码忘记且没有有效恢复材料时，可能无法恢复数据。离线应急方式属于正式产品设计。

### 2.2 本机解锁凭据

自动解锁需要设备持有可恢复资料库密钥的凭据，不能同时声称“不保存任何解锁材料”。

- 持久凭据由用户选择保存，并使用系统凭据存储保护。
- Windows 与 Fedora 的凭据访问分别适配；Linux Secret Service 可能不可用或尚未解锁。
- 凭据服务不可用时回到手动解锁，不回退到明文文件保存。
- 解锁凭据、MCP 接入凭据、会话和一次性授权留在设备本地，不进入同步目录。
- 更换主密码与撤销受信任设备是不同操作，不能假定改主密码必然使所有已保存设备凭据失效。
- 自动解锁默认关闭是当前建议；每台设备独立设置。

用户选择自动解锁意味着信任该设备的系统登录环境。“无须授权”的条目在解锁且客户端获准接入后可被直接访问；另外两态的语义保持不变。

### 2.3 锁定与退出

锁定应使资料库数据操作停止，并撤销未执行的单次授权。过期、锁定、退出后的重试行为必须明确。

后台、网页标签页和资料库解锁会话分别管理。不能仅依赖网页关闭事件判断用户离开；自动锁定与系统锁屏、休眠后的处理待确定。

同步导致资料库标识或密钥配置不兼容时，显示待解锁或不支持状态，不自动新建空库。

## 3. key、description、权限与附件完整性

key 和 description 可以是明文，但不能任意替换后仍被当作可信的原条目信息。

- key、description、条目身份、版本、权限及附件归属需要完整性保护。
- description 是说明资料，不是系统指令，不能改变权限或被当作用户批准。
- description 可免逐次确认地读取，不代表可以任意修改；如向 AI 开放修改接口，需按对应 key 的修改策略执行。
- 不能通过修改文件名，把“拒绝”条目的密文挪到“无须授权”的 key 下取得读取。
- AI 不拥有修改长期策略或接入信任配置的权限。
- key 重命名需保留权限归属；具体条目身份与重命名格式待设计。
- 明文 key 是逻辑名称，不直接等同文件路径、命令或可执行代码。
- 附件上传路径需规范化，处理路径穿越、符号链接、保留名称和覆盖问题。

完整性校验只能证明记录未被未授权修改，不能单独证明它是最新版本。旧的、合法认证过的权限记录仍可能被同步回传。

建议本机记录已知版本关系，对可疑回退或并发策略变更停止自动扩大权限并提示用户。新设备仅拿到一份旧副本时，缺少独立可信状态就无法保证发现回退；跨设备撤销的强度需要另行明确。

## 4. MCP 授权边界

### 4.1 客户端接入与条目授权分开

客户端身份、资料库解锁、key 策略、单次审批是不同层次。

- “无须授权”仅免去逐次确认，不开放匿名或任意本地进程访问。
- “拒绝”直接终止对应请求，不变成一个可随手越过长期规则的确认框。
- 当前建议锁定时拒绝 MCP 数据操作；key + description 的磁盘可见性不等同于开放匿名目录接口。
- 已解锁且获准接入的客户端可以免逐条审批地列出和搜索 key + description，即使该条目的正文读取策略为“拒绝”。“拒绝”不承诺隐藏公开元信息。
- 目录接口只返回明确公开的元信息；资源读取、附件下载、历史版本及导出沿用正文/附件读取策略。
- 正文片段、自动生成的摘要和错误信息可能泄密，不把解密正文或从中生成 description 当作免审批检索的一部分。

### 4.2 真实用户确认

服务端创建待审批请求，可信交互层展示，用户实际操作后回传结果。

禁止把下列内容当作有效批准：

- 模型填写的 `approved: true`。
- AI 复述“用户已经授权”。
- 文件、网页、description、value 或附件中写出的授权指令。
- 可被模型任意调用的、没有独立用户校验的批准接口。

可信 harness 是授权链的一部分。服务端需验证请求关联和来源，而不是仅在界面上做一个拦截器。

### 4.3 批准绑定

单次批准至少绑定：

- 发起客户端及相关会话。
- 请求标识、目标 key 和条目版本。
- 操作类型及正文/附件范围。
- 替换内容或可验证的内容摘要。
- 有效期、单次消费状态和批次范围。

请求变更、版本更新、权限变化、取消、超时或锁定时，原批准不再用于执行。重试要有幂等语义，避免写入已成功但响应丢失后再次执行。

取消或无人应答不视为同意。审批等待需要适配 MCP 超时或挂起/查询机制，不通过扩大权限解决等待问题。

### 4.4 读取与修改分离

- 允许替换不意味着允许读取旧值。
- 展示给用户的旧值或差异不能自动写入模型可见的工具参数、结果或日志。
- 没有读取授权时，错误和版本冲突结果只返回必要状态。
- 读取权限也覆盖附件内容和历史明文，不能通过历史接口取得当前策略禁止的内容。
- 写入结果默认返回状态与版本，不回显正文或附件。

### 4.5 批量语义

当前建议：批量替换先完整校验，再提交整个逻辑批次。存在禁止项时返回说明，不暗中只执行一部分；需要新的目标集合时重新提交请求。

在本机实现一个提交批次，不等于另一台设备同步时也有文件系统事务。跨文件依赖和批次清单的可用性处理见第 7 节。

### 4.6 Harness 能力差异

MCP elicitation 可以承载交互，客户端是否支持、如何呈现以及一次点击能否完成，需要实际验证。

- 主密码和其他新输入的秘密不通过 elicitation 表单收集。
- 支持的客户端使用其审批 UI；其他客户端转本地网页。
- 不把通用工具注解当作安全策略执行器。
- 同一次操作尽量只确认一次，但去重不能跳过服务端授权检查。
- pi 的工具钩子和确认 UI 是适配入口，不代表已有完整的 Keyfolio 审批集成。

## 5. 明文进入 AI 后的边界

返回给 MCP 客户端的正文或附件，可能进入：

- AI 客户端内存及工具历史。
- 会话记录、日志、缓存和临时文件。
- 云端模型服务的请求及其数据处理流程。

用户同意读取时，应清楚这代表允许内容离开保险库进入客户端，而非“只在本机借用密钥”。

本地资料库不落明文，不能保证 harness 也不落明文。曾查阅的 pi 文档描述过大型工具结果和部分资源可能保存为临时文件；接入时应核对当前版本行为，并按内容类型和大小测试。

“让程序代用密钥完成操作、只返回结果”是另一个能力，不在通用明文读取的承诺内。如后续实现，需要限制目标服务和允许操作，避免变成任意带凭据请求代理。

## 6. 本地网页与程序边界

- 服务仅监听本机地址；本地监听仍需身份验证、会话保护及 Host/Origin 检查。
- 对网页操作防范 CSRF；不要配置任意来源可用的 CORS。
- 不把主密码或持久解锁凭据放入浏览器 localStorage。
- 网页资源随程序分发，不依赖远程 CDN、脚本或遥测服务。
- Markdown 按不可信内容渲染；过滤危险 HTML/URL，不执行脚本，不默认加载外部跟踪资源。
- 附件预览、解压和下载有独立的类型、大小及路径检查。
- 默认不记录正文、密码、Token、解锁凭据和附件明文。
- 日志只保留排错需要的状态与操作元信息，内容和保留期另行确定。
- 导出明文或下载解密附件属于用户主动操作，应提示保存位置与范围。

Go 的垃圾回收、字符串复制和浏览器运行时都限制了“立即彻底擦除所有明文”的可保证程度。减少秘密副本、缩短驻留时间、避免崩溃转储泄密需要专项实现与验证，不能用变量赋空代替承诺。

程序和设备状态建议存放在资料库同步目录之外。同步下载的程序更新不能未经可信来源校验就执行，否则可能窃取下一次输入的主密码。

## 7. 外部同步、文件变化与一致性

### 7.1 外部同步是并发写入者

应用不控制同步顺序、时间和原子性。不能依靠本机文件锁阻止坚果云覆盖文件，也不能假设收到一次通知意味着整组文件已经到齐。

当前建议的存储方向是不可变版本记录、父版本关系和批次清单；其准确格式仍需设计。

### 7.2 接收候选内容

- 临时文件和未完成记录不进入当前视图。
- 文件大小暂时稳定不等于完整；需验证格式和密码学完整性。
- 正文、附件和依赖清单按完整性关系检查。
- 文件监听结合启动扫描和补充扫描，处理事件丢失、合并及重复。
- 候选版本通过校验后再替换当前可用视图。
- 文件操作应处理正在占用、权限拒绝、临时消失、重复创建等正常异常。

本机的原子改名只保证该次本地操作，不能推断同步接收端也原子。

### 7.3 各类状态的行为

| 情况 | 建议行为 |
| --- | --- |
| 半文件、缺依赖 | 标为更新中，等待完整版本，不发布半条目 |
| 附件未到齐 | 标明附件不可用；若属于整批提交依赖，则整批等待 |
| 正在编辑时外部替换 | 保留草稿和基线版本，提示比较或合并 |
| 同一父版本出现多个子版本 | 标为冲突，两份均保留，不按时间戳静默覆盖 |
| 外部删除 | 标为缺失/删除，保留未保存草稿；不自动用缓存复活文件 |
| 损坏或认证失败 | 保留诊断状态，不自动初始化空内容 |
| 不支持的格式版本 | 提示升级或受限访问，停止对不理解的数据写入 |
| 资料库标识/密钥配置异常 | 暂停库级数据操作，回到可解释的错误或解锁状态 |
| 当前批准涉及的数据变化 | 取消旧执行资格，重新发起或确认 |
| 一部分 key 异常 | 对受影响内容暂停操作，其他有效条目继续服务 |

上次已验证版本可以供人类查看，但应标为历史或过期。不能在当前版本不明时，把缓存里的旧 Token 当最新值返回给 AI。

### 7.4 并发写入

单机“保存前再检查一次版本”不能解决两台离线电脑同时修改的问题。保存必须保留来源版本，识别分支，并留有恢复依据。

冲突判断基于版本关系和内容身份，而非仅比较文件名或修改时间。外部工具生成的冲突副本也需识别，不能悄悄变成另一条独立、权限不同的记录。

### 7.5 批次与清理

逻辑批次只在全部记录、附件及提交标记有效且完整时应用。文件到达顺序任意，清单先到或后到均应处理。

历史清理、附件回收与删除标记必须考虑离线设备和延迟同步。保留时长、空间限制、清理确认和旧设备回归流程尚未确定。

### 7.6 本地缓存

不把一个正在写入的 SQLite 数据库文件直接当作需要跨设备同步的权威资料库。

SQLite 或其他索引存储可作为设备本地、可重建的实现候选；是否使用及明文缓存策略另定。当前文件方案仍需提供独立扫描与恢复能力。

## 8. 跨平台与分发

Go 与 Rust 都可以实现本项目，当前已选 Go。跨平台指按系统和架构分别构建、测试、发布，不指同一个可执行文件在所有系统运行。

需要验证：

- Windows 与 Linux 的文件占用、替换、监听和持久化行为。
- 大小写、Unicode 规范化、路径分隔符及 Windows 保留文件名。
- 系统凭据服务的可用性、锁定状态及错误恢复。
- 用户级自启动和系统登录会话关系。
- 不同程序版本对同一资料库格式的兼容行为。

尽量选用无 cgo 依赖的实现以简化构建，但不能仅因“编译成功”就宣称跨平台功能已验证。系统凭据与自启动可能仍依赖操作系统提供的服务。

前端框架、加密库、SDK 的具体版本需在实现时核对、固定并维护。语言本身不提供授权正确、无数据丢失或无秘密残留的保证。

## 9. 恢复、备份与导出

- 坚果云同步与其历史版本不代替独立备份。
- 备份包含恢复所需的资料库参数、内容及附件，而不只是部分密文文件。
- 保留独立加密备份，并用合成数据演练恢复。
- 提供格式说明及离线恢复/导出工具，避免仅能依赖某个正在运行的服务打开数据。
- 明文导出是显式操作，不写到默认同步或项目源码目录。
- `.gitignore` 只是辅助，不能作为秘密不会被提交的保证。
- 密钥轮换与主密码更改须考虑旧备份中的有效旧密文及凭据，不宣称修改密码会自动抹去旧副本。

## 10. 首版之外的明确边界

- 不是原生 Passkey 认证器。设备绑定且不可导出的 Passkey 不会因为建立资料库就变成可迁移文本。
- 不把“所有手机都能打开加密 7z”或“一个扩展覆盖所有浏览器”作为架构前提。
- 不在首版实现手机端、自动填充、网页登录监听或 Cookie 收集。
- 后续网页剪藏按不可信输入处理，与自动捕获凭据分开。
- 不在当前阶段实现浏览器扩展或原生桌面 GUI。
- 不实现坚果云登录、WebDAV 同步或自建云端保险库服务。
- 不自动允许 AI 删除、重命名条目或修改权限；这些接口如增加需单独定义语义。

## 11. 验收清单

以下使用合成数据验证；通过这些检查也不等于完成独立安全审计。

### 11.1 数据与加密

- [ ] 同步目录中没有意外的正文、附件明文或解锁凭据。
- [ ] 正确密码可打开资料库，错误密码得到明确失败。
- [ ] key、description、权限、附件归属、密文或版本元数据被篡改时能检测或拒绝。
- [ ] 大附件中断、截断、重排和重复片段按所选格式验证。
- [ ] 用完整备份及主密码在另一台设备恢复成功。
- [ ] 主密码更改、设备凭据失效和旧备份恢复行为有测试。

### 11.2 授权与 AI

- [ ] AI 优先取得 key + description；发现接口不夹带正文、附件或解密生成的摘要。
- [ ] 每个 key 的读取/修改三态分别生效。
- [ ] 免确认仍要求客户端接入和资料库解锁。
- [ ] 修改授权不泄露旧 value，附件和历史接口不绕过读取策略。
- [ ] 多个 key 的审批范围准确，禁止项不会被批量同意覆盖。
- [ ] 替换内容、版本或策略变化后旧批准失效。
- [ ] 伪造批准、重复消费、跨会话复用、超时和锁定均正确处理。
- [ ] harness 与网页审批不会重复执行同一请求。
- [ ] harness 不支持交互或不可用时，存在网页路径或明确拒绝。
- [ ] 工具结果、客户端日志、临时文件和云端传输行为已实际检查。

### 11.3 外部文件变化

- [ ] 同步过程中持续读取与编辑，应用保持响应且不静默覆盖草稿。
- [ ] 半文件、缺附件、清单乱序和重复通知得到正确状态。
- [ ] 两台离线设备修改同一旧版本后能识别并保留冲突。
- [ ] 外部删除不会触发自动空库重建或缓存内容复活。
- [ ] 批量版本到达不完整时不发布半批更新。
- [ ] 程序保存中断或重启后能恢复到明确的有效状态。
- [ ] 不支持的格式不会被旧程序误写。
- [ ] 受影响 key 暂停操作，正常 key 仍可用；库级异常单独处理。

### 11.4 平台与网页

- [ ] Windows 和 Fedora 分别验证凭据存储、自启动和自动解锁。
- [ ] 凭据服务不可用时正常回退至手动解锁。
- [ ] 本地接口身份、会话、Origin/Host、CSRF 和 CORS 行为测试通过。
- [ ] Markdown、附件及 key 的恶意输入不能执行脚本或越过文件路径范围。
- [ ] 关闭网页后后台与 MCP 的行为符合设置。
- [ ] 锁定、休眠、退出及重启时会话与待审批请求得到一致处理。
