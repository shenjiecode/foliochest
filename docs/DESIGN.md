# FolioChest / 资料匣 项目设计

- 状态：设计基线，已获授权开始实现；实际进度见 README。
- 整理日期：2026-11-25。
- 已确认名称：FolioChest / 资料匣（原名 Keyfolio）。
- 阅读对象：项目所有者、开发者及接入项目的 AI Agent。
- 配套文档：[边界与安全说明](BOUNDARIES.md)。

本文记录当前产品理解和技术方向。标为“已确认”的内容来自本轮讨论；具体实现建议和待验证事项分别列出。

## 1. 项目定位

FolioChest / 资料匣是一个本地运行的加密资料库，通过网页管理，通过 MCP 向 AI 提供按 key 控制的读取和修改能力。

它用于统一保存 Markdown、文本、项目资料和各种附件，也可以保存网站账号密码、恢复码、API Key 及可导出的密钥。用途不限定为密钥或密码管理。用户掌握资料库文件，只需要记住一个主密码；每台受信任电脑可以选择保存本机解锁凭据。

日常体验：

> 启动本地程序 → 在网页解锁或自动解锁 → 查看和编辑条目 → AI 通过 MCP 申请操作 → 按权限自动执行或由用户确认。

坚果云等外部工具负责把资料库文件同步到其他设备。每台设备运行自己的程序和 MCP 服务。

## 2. 已确认的产品决策

| 项目 | 当前决定 |
| --- | --- |
| 使用设备 | 首版面向 Windows 和 Fedora/Linux 电脑，暂不考虑手机 |
| 应用形态 | 本地后台服务 + 浏览器网页 + MCP，无原生桌面 GUI |
| 开发方向 | Go 后端，React + TypeScript + shadcn/ui 网页，构建资源随程序分发 |
| 内容组织 | 明文 key + description + 单层 group、加密 value、独立的加密附件列；每条最多一个组，未选择为未分组 |
| AI 发现条目 | 优先读取 key、description、group，可按组筛选，按需申请正文与附件，类似 skills 的 name-description 发现方式 |
| value 内容 | 支持文本、Markdown 等内容，不要求正文继续拆成固定字段 |
| 人类解锁 | 一个主密码；解锁操作在本地网页进行 |
| 受信任设备 | 支持选择开机启动、自动登录/自动解锁，两项独立配置 |
| AI 能力 | 支持读取，也支持提交替换；可一次操作多个 key |
| AI 权限 | 每个 key 的读取、修改分别设置三态策略 |
| 授权状态 | 无须授权、需要授权、拒绝 |
| 授权体验 | 优先在 harness 的 CLI/App 中同意或拒绝；本地网页提供审批入口 |
| 同步职责 | 外部文件系统同步，不在应用内实现坚果云协议或账号管理 |
| 运行时文件变化 | 能处理同步造成的替换、删除、不完整文件和冲突，保持应用可用 |
| 文档组织 | 主设计描述产品与流程，边界及防御性说明单列 |

## 3. 用户与典型内容

### 3.1 使用者

- 人类用户：管理资料库、内容、设备和授权。
- AI 客户端：通过已接入的 MCP 调用读取或提交修改。
- 外部同步工具：独立同步文件，不参与应用的登录、解密和审批。

### 3.2 条目示例

以下均为结构示例，不含真实凭据。

| key | description（明文说明） | value 的用途 | 附件示例 |
| --- | --- | --- | --- |
| `GitHub/登录资料` | GitHub 账户的登录资料及说明 | 账号说明与凭据 | 无 |
| `GitHub/恢复码` | GitHub 账户的恢复码及使用记录 | 恢复码与记录 | 原始恢复码文件 |
| `项目A/API配置` | 项目 A 开发环境所需的 API 配置 | 配置文本或 JSON | 配置附件 |
| `项目A/部署说明` | 项目 A 的部署步骤与运维说明 | Markdown 文档 | 部署相关文件 |
| `服务器A/证书` | 服务器 A 的证书和相关密钥资料 | 用途、到期信息和更新说明 | 证书与可导出的私钥文件 |

key 负责识别，description 说明内容及用途。它们与 group 一起作为 AI 优先阅读的发现信息保持明文，正文和附件按需读取。

## 4. 条目模型

### 4.1 逻辑结构

| 字段 | 用途 |
| --- | --- |
| `key` | 用户可读的唯一名称，明文保存 |
| `description` | 说明条目内容和用途，明文保存，供 AI 优先检索与判断 |
| `group` | 可选的单层分组，明文且受完整性保护；空字符串为未分组，仅人类可改 |
| `value` | 加密正文，可以是纯文本、Markdown、JSON 等 |
| `attachments` | 零个或多个加密附件 |
| `read_policy` | AI 读取策略 |
| `write_policy` | AI 修改策略 |
| 版本信息 | 由程序管理，用于替换、历史记录和冲突识别 |

这是逻辑模型，不是已经冻结的磁盘格式或接口字段规范。

附件以独立列展示，与所在 key 关联。授权单位仍然是 key；一次请求同时说明要访问 value、指定附件，还是整个条目。正文和附件可以分别请求、分别替换。

### 4.2 正文编辑

- 默认提供文本和 Markdown 编辑能力。
- Markdown 可在编辑和预览之间切换。
- JSON 等内容可以按文本保存，具体专用编辑能力后续确定。
- 用户通过网页上传、下载和替换附件。

### 4.3 检索

- 按明文 key、description、group 查找条目，可按组精确筛选。
- AI 首先获取 key + description + group 的目录或搜索结果，判断条目是否相关。
- 找到相关条目后，再按 key 的读取策略申请 value 或附件。
- 在资料库已解锁且客户端已接入的前提下，读取 key + description + group 无需逐条审批；三态读取策略约束正文、附件等受保护内容。
- 网页解锁后可选择同时检索正文。当前直接在内存中匹配，不持久化明文索引，不向 MCP 开放正文搜索或结果片段。
- description 由用户维护；检索默认返回已保存的说明，不先解密正文生成摘要。

### 4.4 删除与重命名（`0.4.0-dev`）

- 人类网页提供重命名与移到回收站，不添加对应 MCP 工具。正文草稿先保存或放弃，再进行管理操作。
- entry_id 是稳定身份，key 是当前名称。重命名生成新版本，保留正文、附件与权限；旧名称不是别名，可以在不再被当前分支占用后另行使用。
- 删除生成带 `deleted: true` 的认证版本，正文与附件为空；旧内容和附件留在历史中，不释放空间。正常已删除条目不出现在日常列表、正文搜索及 MCP 发现结果中，回收站保留其当前名称。
- 回收站选择删除前版本恢复为新版本，保持当前权限，可明确填写恢复后的 key。恢复旧版本默认保留当前名称，不自动撤销一次重命名。
- 同一身份存在多个分支时，全部候选名称都展示冲突。合并/恢复或删除全部分支要求用户确认全部当前 heads；权限逐项取更严格策略。不同身份的同名冲突继续阻止操作，暂不提供自动处理。

### 4.5 单层分组（`0.5.0-dev`）

用户已确定采用单层分组，不做多级目录或多重归属。每条资料最多一个 `group`，空字符串表示“未分组”；与 key 独立，key 仍全库唯一，现有 key 中的斜杠不解释为分组。暂不添加 tags。

- group 是公开元信息，供网页与 MCP 检索、精确筛选；名称只用于定位，不是权限或授权指令。AI 不得修改分组，移动不改变长期读写策略。
- 组名为 1–64 个字符，不允许控制字符、斜杠、反斜杠和首尾空白；“未分组”保留为界面名称。留空解除分组。
- 分组从当前条目与回收站条目推导，不保存独立空组。输入新组名保存即创建；全部成员移走后该组消失。
- 侧栏选择组，全部条目按组折叠；可批量移动。组重命名或移除绑定已查看的全部成员（含回收站）及版本，移除只解除分组、不删除内容。组内有冲突/缺失版本时，先处理异常。
- 管理批次沿用最多 20 条及 8 MiB payload 上限；大组需手动分批移动，不偷偷拆成非原子批次。外部离线写入仍可能使旧组再次出现。
- 正常编辑、AI 替换、key 重命名与删除保留当前组；历史恢复默认保留当前组，可明确修改。并发分组分歧须人类选择，列表保留全部候选组，不静默挑选。
- 新组字段使用格式 3。格式 1/2 继续原有读写；使用分组前在网页显式升级，不重写历史。改名不改变加密域、设备凭据命名空间或已有目录。
- 产品和主程序名称为 FolioChest / `foliochest`，只保留一个命令入口。仓库、Go module、现有配置路径及磁盘认证标识不变，不搬动运行资料。

## 5. 权限模型

### 5.1 三态策略

| 状态 | 执行方式 |
| --- | --- |
| 无须授权 | 用户已预先允许该类操作，不再逐次确认 |
| 需要授权 | 生成待审批请求，用户同意后执行 |
| 拒绝 | 返回拒绝结果 |

“无须授权”指免逐次确认，仍沿用资料库解锁状态和客户端接入关系。

读取和修改各自设置，例如：

| key | 读取 | 修改 |
| --- | --- | --- |
| `项目A/说明文档` | 无须授权 | 需要授权 |
| `开发环境/API配置` | 需要授权 | 需要授权 |
| `主账户/恢复码` | 拒绝 | 拒绝 |

网页中的人类操作与 AI 操作身份分开。三态用于约束 AI 访问；用户在网页管理内容及策略。

### 5.2 读写分离

读取授权使 AI 获得批准范围内的明文。

修改授权使 AI 提交的新内容可以写入指定 key，不自动包含读取旧内容的权限。AI 可以提交完整替换内容；如果需要基于旧内容编辑，则先取得相应读取权限。

首版 AI 修改以替换 value、添加或替换所选条目附件为目标。AI 新建、删除条目和重命名 key 的接口范围另行确定。

### 5.3 批量请求

一次请求可以列出多个 key 及各自操作。需要审批时，用户在一个确认界面查看范围并同意或拒绝。

建议的审批内容：

- 请求来自哪个客户端、哪个会话。
- 本次涉及的 key。
- 操作是读取还是替换。
- 操作范围是正文还是具体附件。
- 提交的新内容或变更预览。
- 本次请求的执行范围。

一次确认对应本次具体请求，不改变条目的长期策略。

### 5.4 建议的默认行为

以下为待实现验证的默认方案：

- 新条目的读取、修改均设为“需要授权”。
- 用户通过网页维护长期权限策略。
- 单次批准只覆盖列出的 key、操作和具体版本。
- 批量替换按完整批次提交；禁止项先返回说明，由调用方调整请求。
- 替换保留加密历史版本，执行结果返回状态和版本信息。

## 6. 使用流程

### 6.1 首次使用

1. 用户运行本系统对应的程序。
2. 未指定且未记住资料库时，网页显示“尚未选择资料库”，提供创建、打开和从备份恢复，不预填开发目录。已选库的位置缺失时保留原路径并提示检查目录或同步，不转成首次使用或自动重建。
3. 创建先选择新/空文件夹，再设置主密码；取消不切换当前库。打开已有库先选择包含库文件的目录，再输入主密码。目录控件提供系统文件夹选择器，也可手动输入绝对路径；选择器取消不修改输入，系统环境不支持时明确提示。
4. 程序解锁资料库，网页进入管理界面，MCP 数据操作可用。
5. 用户按需接入 AI 客户端。
6. 用户可以为本机开启自动启动或自动解锁。

持久保存本机解锁凭据由用户选择。新设备读取同步来的资料库后，独立完成自己的登录和设备设置。

### 6.2 日常管理

1. 用户在侧栏选择单层分组，或在全部条目中按 key、description、group 查找资料。
2. 打开条目，维护 description、查看或编辑 value、管理附件。
3. 保存后生成新的内容版本。
4. 外部同步工具把更新后的资料库文件同步到其他设备。

### 6.3 AI 读取

1. AI 优先读取 key + description + group，定位一个或多个相关条目。
2. 提交按 key 的读取请求，列出正文或附件范围。
3. 服务读取当前策略：直接执行、进入审批或拒绝。
4. 需要审批时，用户在 harness 或网页同意/拒绝。
5. 服务返回获准的内容。

### 6.4 AI 替换

1. AI 提交目标 key、替换内容、附件范围及基于的版本。
2. 服务生成变更预览。
3. 按修改策略执行或等待审批。
4. 需要审批时，用户确认具体变更；免确认策略直接继续。
5. 服务检查当前版本并提交，保留历史记录。
6. AI 获得操作结果和新版本标识。

如果 AI 未获准读取旧 value，可使用仅用于并发控制的版本标识提交整体替换；版本标识的接口形式待确定。

### 6.5 同步期间工作

- 未编辑的条目接收验证完成的新版本后刷新。
- 有未保存内容的编辑器保留草稿，并提示外部版本变化。
- 发生并发分支时展示冲突，让用户选择或合并。
- 未到齐的文件显示更新状态。
- 无法使用的条目显示具体状态，其他正常条目继续可用。

## 7. 网页与后台形态

### 7.1 全部人类配置放在网页

计划页面：

| 页面 | 主要操作 |
| --- | --- |
| 资料库入口 | 创建、打开、解锁、锁定 |
| 条目列表 | 显示和搜索 key + description、查看状态、进入编辑、配置权限 |
| 条目编辑 | 维护 description、编辑 value、预览 Markdown、管理附件 |
| 授权请求（备用） | 顶栏仅有未处理请求时提示，日常确认优先留在 harness |
| 历史与冲突 | 查看版本、恢复内容、处理并发修改与候选名称 |
| 回收站 | 查看已删除条目、选择删除前版本恢复 |
| 设置 | 资料库位置、本机自动启动/解锁、浏览器记忆、自动锁定、主密码变更、客户端接入 |

首版不提供原生桌面窗口或托盘界面。浏览器打开方式和后台安装方式按系统适配。

### 7.2 进程与会话

本地后台承担 HTTP、资料库操作、凭据访问和 MCP。网页是操作入口，不是维持 MCP 运行的前提。

建议关闭网页标签页后保持后台运行；锁定和退出由明确操作及自动锁定设置控制。当前原型的网页空闲锁定默认关闭，可在本机设置 0–1440 分钟；网页操作续期，后台轮询和 MCP 不续期。

本机自动启动与自动解锁分开：

- 自动启动：登录操作系统后启动后台。
- 自动解锁：使用这台设备保存的解锁凭据打开资料库。
- 人工解锁：在网页输入主密码。
- 自动锁定：按用户设置结束当前解锁会话。

`0.3.0-dev` 已实现前述设置，默认关闭自启动与自动解锁。自启动注册当前固定路径的程序，仅在操作系统登录后启动服务，不打开浏览器。Linux 使用 XDG Autostart，Windows 使用当前用户 Run 项；系统凭据分别使用 Secret Service 和 Credential Manager。

开启设备自动解锁需要重新确认主密码。每次进程启动只尝试一次；手动、空闲或系统事件锁定后由用户重新解锁。用户还可单独选择记住当前浏览器 90 天，使其在后台自动解锁后进入网页；未记住的浏览器仍需主密码。每份本机配置暂支持记住一个浏览器，新授权替换旧记忆。

`0.4.0-dev` 增加独立的系统事件锁定设置，默认开启。监听系统锁屏、会话切换/断开和休眠/恢复事件，调用同一个锁定与审批撤销流程。启动自动解锁需先确认系统监测就绪、会话可用；手动解锁仍受已知系统锁定状态约束。通知不可用时显示提示，不静默宣称已受保护。具体延迟、失败回退和内存边界见 BOUNDARIES。

### 7.3 主密码变更

在设置页输入当前主密码和两遍新主密码，确认后重新包装原库密钥，内容、附件和历史不重写。完成后锁定资料库、撤销当前会话及审批，并关闭本机自动解锁；其他设备收到新配置后重新解锁和授权。建议操作前下载备份并暂停其他设备写入。密码变更与数据密钥轮换的边界见配套安全文档。

### 7.4 显式格式升级

新库使用实验性格式 3。格式 1/2 继续支持原有读写，品牌改名、打开或改主密码不会自动迁移。分组需格式 3；删除和 key 重命名需格式 2 或更新。人类先备份、更新全部设备程序至 0.5.0-dev 或更新、暂停其他写入，再在设置页明确确认目标格式 3 并输入主密码。升级仅重包装库密钥和更新配置，不改写历史；完成后锁定、停用本机设备授权和浏览器记忆。旧网页的格式 2 升级确认不能沿用；旧程序拒绝格式 3 配置。同步顺序和旧设备运行边界见 BOUNDARIES。

## 8. Harness 与 MCP 接入

### 8.1 统一操作入口

网页中的 AI 审批和 MCP 请求共同使用后台的操作管理模块。后台维护请求状态、目标范围、版本和执行结果。

计划能力包括：

- 列出或搜索 key + description + group，可按 group 精确筛选，作为 AI 的默认发现入口。
- 请求读取一个或多个条目的指定内容。
- 提交一个或多个条目的替换。
- 查询请求和执行状态。

具体工具名称、参数和返回结构在接口设计阶段确定。

### 8.2 审批展示

按客户端能力选择：

1. 支持 MCP elicitation 的 harness：使用其交互能力展示审批。
2. 支持扩展的 harness：通过适配层展示确认界面。
3. 其他客户端：在本地网页的待审批页面处理。

日常路径是在发起请求的 harness 内由人类确认，资料匣后台校验并执行；网页仅是备用处理入口，不要求日常跳转网页。两边对应同一请求，处理一次即可，不重复执行。客户端不支持交互式确认时明确引导网页，不静默放行。实际 pi 等 harness 的确认界面仍待端到端验证。

pi 可作为首个适配验证对象：已查阅的安装文档提供 MCP 工具调用钩子及确认 UI。接入方案尚未实现，也未验证具体版本的端到端审批。

### 8.3 传输与解锁状态

建议一台设备上的资料库主服务统一维护解锁状态和待审批操作。

MCP 采用本地 HTTP 还是 stdio 桥接、是否首版同时支持，留到接入验证阶段确定。若采用 stdio 桥接，桥接连接既有资料库服务，不另建互相独立的解锁状态。

## 9. 文件存储与外部同步

### 9.1 职责划分

应用负责本地内容、加解密、版本、权限和文件变化处理。

坚果云等外部工具负责传输文件。用户在外部配置同步目录，应用不管理坚果云账号，也不实现其同步协议。

### 9.2 两类数据

**资料库目录，可由外部工具同步：**

- 明文 key + description + group、加密 value、加密附件。
- 条目权限及必需的资料库元数据。
- 加密参数、格式版本、内容版本。

**设备级目录，留在本机：**

- 系统相关设置、程序安装状态。
- 本机解锁凭据和客户端接入凭据。
- 当前解锁会话、待审批请求、一次性授权。
- 可重建的索引、缓存及必要运行状态。

### 9.3 建议采用的落盘方案

逻辑上按 key 替换内容，物理上采用不可变版本记录，记录父版本关系。正文和附件的具体文件布局待定。

配合：

- 本机写完候选文件后发布完成版本。
- 通过文件监听及补充扫描发现外部变化。
- 验证完成后更新当前可用视图。
- 对同一旧版本产生的多个分支展示冲突。
- 用批次清单表达一组替换，完整到达后再应用。
- 通过删除版本表达应用内删除操作。

原型现采用不可变的单文件批次：一个批次包含本次所有条目的明文元信息与加密正文/附件，统一校验后接纳；所有父版本依赖到齐后，该批次才可使用。这样先实现整批保存，不引入多文件附件清单。具体实验性格式见 [FORMAT.md](FORMAT.md)，正式格式尚未冻结。

### 9.4 应用状态

条目可展示正常、更新中、冲突、缺失、损坏或版本不支持等状态。库级解锁或格式变化通过资料库状态展示。

历史版本和草稿有明确标识；AI 使用的是当前可执行请求所对应的内容版本。

## 10. 技术架构

```text
人类用户 ── 浏览器网页 ─────────────┐
                                  │
AI harness ── MCP / 审批适配 ──────┤
                                  ▼
                         Go 本地后台服务
                    ┌─────────────┴────────────┐
                    │ 资料库、版本、权限、审批 │
                    │ 加密、文件变化、系统适配 │
                    └─────────────┬────────────┘
                                  │
                             资料库文件
                                  ↕
                         外部文件同步工具
                                  ↕
                       另一台电脑的资料库文件
```

### 10.1 当前语言方向

- 后端：Go。
- 网页：React + TypeScript + shadcn/ui 本地组件；Tailwind CSS 与 esbuild 构建。只保留一套正式界面，不设置模拟后端、预览入口或旧 DOM 回退。
- 分发：网页构建产物嵌入可执行程序。
- MCP：优先评估官方 Go SDK。
- 平台：优先 Windows 与 Fedora/Linux，按系统和 CPU 架构构建。

目标运行环境不需要安装 Go 或 Node.js。系统凭据、自启动和文件操作由平台适配层处理。

### 10.2 模块划分建议

| 模块 | 职责 |
| --- | --- |
| Web | 静态页面、会话与人类操作接口 |
| Vault | 条目、附件、版本和资料库状态 |
| Crypto | 密码派生、密钥保护、正文与附件加密 |
| Access | 客户端身份、三态策略、请求范围 |
| Approval | 审批生命周期、变更预览、执行绑定 |
| MCP | 工具接口、请求结果、客户端交互 |
| Storage | 文件发布、变化检测、扫描与冲突 |
| Platform | 凭据存储、用户级自启动、系统会话/电源事件 |

模块划分表达职责，不要求分别运行成多个服务。

## 11. 首版范围与实施顺序

### 11.1 首版目标

- Windows、Fedora/Linux 本地运行。
- 网页创建/打开资料库、解锁、锁定和设备设置。
- key + description + value、Markdown、加密附件和基本搜索。
- 读取/修改三态策略。
- MCP 读取与替换、多个 key 批量请求。
- 网页审批及一个主要 harness 的审批适配。
- 外部文件变化检测、历史、冲突和恢复。
- 自动启动及受信任设备自动解锁。

### 11.2 后续候选，不进入当前首版

- 手机端。
- 浏览器扩展和网页剪藏。
- 自动捕获或填写账号密码。
- Passkey 认证器。
- 更多 harness 的原生审批适配。
- AI 新建、删除、重命名的完整管理接口。
- 让程序代用密钥执行操作、仅向 AI 返回结果的专门工具。

网页剪藏如果后续加入，以用户主动选择标题、网址或选中文字并预览保存为方向，和自动捕获登录凭据分开规划。

### 11.3 建议开发顺序

1. 定义资料库格式、版本模型和离线恢复方式；建立合成数据测试。
2. 实现本地服务及网页基本管理流程。
3. 实现外部文件变化处理与跨系统测试。
4. 实现三态策略、读取/替换和网页审批。
5. 接入 MCP，验证 pi 等 harness 的一次确认流程。
6. 完成系统凭据、自启动、自动解锁和发布打包。
7. 按配套文档完成验收，再决定真实数据试用范围。

## 12. 待确定事项

已确认的方向无需重新讨论；以下细节在实现前或原型中确定：

## 13. 讨论收敛记录

- 需求最初是统一管理账号密码、恢复码、Key 和密钥，并让多设备上的 AI 按授权协助。
- NotebookLM、云盘明文文档未作为资料库方案；外部云盘只承担文件同步。
- 用户不采用 KeePassXC、Bitwarden 等现成密码管理器作为产品主体，选择自有可控程序和文件。
- 手工维护加密分片、逐次执行 age/GPG/7z 命令的操作方式被本地应用取代。
- 内容曾考虑按 Markdown 文档组织，最终采用明文 key + description 与加密 value/附件；Markdown 作为 value 的一种内容形式保留。
- 用户补充 description，类似 skills 的 name-description：AI 优先读取两项元信息，判断相关性后再按权限获取内容。
- 用户明确希望 AI 能在许可下替换内容，不采用只读 MCP。
- 手机与浏览器扩展推迟，首版专注电脑。
- 同步交给外部文件工具，程序承担运行期间数据变化的处理。
- 交互全部采用网页，不做原生桌面 GUI。
- 最终选定 Go 作为当前后端方向。
- 用户确定产品名称为 FolioChest / 资料匣，采用每条最多一个组的单层分组，暂不采用 tags、多级目录或多重归属。

## 14. 网页界面

### Overview

沿用用户确认的整体改版方向：删除说明书式文案、拆分入口流程、固定视口、统一组件。React 页面调用真实 HTTP API，旧 DOM 前端、内存示例和独立预览服务已删除，不保留切换开关或归档副本。

- Design Read：个人资料管理 Web App；安静、以阅读和操作为主的工具界面；Redesign · Overhaul。
- 五项取向：布局变化 4/10、动效 2/10、信息密度 7/10、图片依赖 1/10、品牌保真 7/10。
- 场景定位：入口解锁、工作区查找/阅读/编辑、设置处理低频配置。近距离电脑操作，不使用营销页标题。
- 保留现有字标、颜色、字体、产品模型、权限和安全边界。只做一个方向，不提供装饰变体。
- 正式构建为 React + TypeScript + shadcn/ui 本地组件、Tailwind CSS、esbuild；静态资源嵌入 Go 程序。
- 会话、列表、正文搜索、条目与历史加载具有独立生命周期；列表刷新不取消编辑。锁定/CSRF 更新清除敏感界面，旧响应不能重新显示正文。异步文件读取完成后再次检查所属会话与组件。
- 历史恢复和组管理绑定用户已查看的完整版本快照；界面不推导批准、不隐式升级格式、不跳过后端校验。

### Colors

沿用文件头的具体颜色。主色只用于主操作、选中状态和焦点；红色用于危险操作，棕色用于真实警告。不用渐变或新增装饰色。

### Typography

沿用本机字体与 Georgia 文字字标，不请求远程字体。导航和控件 14px，阅读正文 16px，工作区标题 20–24px，正文一级标题 30px，解锁标题 26px。代码使用等宽字体。

### Layout

- 入口：区分未选择、当前库待解锁、已选位置不可用三种状态；打开、创建、备份恢复分别在独立对话框中完成，不称为注册/登录。目录输入旁使用同风格“选择文件夹”按钮，创建分为选位置与设密码两步。
- 本次为 Extension：保留字标、颜色、密度、内部滚动和控件样式，只补首次使用与系统目录选择。系统对话框由本机后台按显式网页请求打开，不增加原生主窗口、预览或网页文件系统浏览接口。
- 工作区：224px 导航 + 320px 列表 + 剩余阅读/编辑区；顶栏 60px。正文、附件、属性切换，历史和管理操作按需打开。
- 设置：资料库、安全、设备、MCP 四个分区；改密码和升级属于独立确认流程。
- 授权：默认在 harness 中确认。网页不在主导航常驻“待审批”，有未处理请求时才在顶栏显示辅助入口；处理后提示消失。请求来自实际后端；`/#approvals` 仅用于定位备用页面，不提供授权。
- 网页根容器固定 `100dvh`，每个布局子项可收缩（`min-width: 0; min-height: 0`）；列表、正文、导航溢出区、设置和对话框内容各自 `overflow: auto`。不隐藏内部滚动条来截掉内容。
- 1120px 以下收窄导航和列表；900px 以下导航进入抽屉；680px 以下列表和条目分屏切换并提供返回。短视口中入口与对话框内容仍可滚动到全部操作。

### Elevation & Depth

主区域靠分隔线区分，不堆卡片。对话框与菜单使用 `0 16px 48px rgb(32 41 36 / 12%)` 阴影和 `rgb(32 41 36 / 24%)` 遮罩。

### Shapes

控件 6px、对话框 12px 圆角；不使用大圆角包围整个工作区。图标来自本地打包的 Lucide，仅表示操作，不替代品牌字标。

### Components

shadcn/ui 本地源码位于 `web/src/components/ui/`，业务页面位于 `web/src/features/`，会话、请求和文件处理位于 `web/src/lib/`。不用字符串拼接页面；只有经过安全配置的 Markdown 渲染结果使用 HTML 注入。

按钮、输入、对话框、菜单、标签页、选择、开关与提示使用统一规则，提供加载、空结果、错误、忙碌和可见焦点状态。提交时防重复操作，失败恢复控件；设备授权失败后重读实际状态。过渡 120–160ms，尊重 reduced-motion。

### Do's and Don'ts

- 显示必要的状态、错误、危险确认；短文案不等于删除安全提示。
- 只有真实接口成功后才显示保存结果；不在客户端模拟持久化、授权或设备设置。
- 不增加 tags、多级分组、组级权限、空组持久化或新后端能力。
- 本轮只做一个方向；不往产品里加入配色试验面板、广告文案或装饰图。
- CSP 保持外部同源脚本，Radix 的动态样式使用每页随机 nonce；不增加 unsafe-inline 或 unsafe-eval。
- 组件测试、隔离运行检查和交叉构建不代表实际 harness、目标系统真机或独立安全验收。
