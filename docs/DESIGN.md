# FolioChest / 资料匣 项目设计

- 配套文档：[边界与安全说明](BOUNDARIES.md)、[文件格式](FORMAT.md)。

## 1. 项目定位

FolioChest / 资料匣是一个本地运行的加密资料库，通过网页管理，通过 MCP 向 AI 提供按 `key` 控制的读取和替换能力。

> 启动本地程序 → 在网页解锁或自动解锁 → 管理条目与权限 → AI 通过 MCP 检索公开元信息并按策略读取或提交替换。

外部文件同步工具（如坚果云等）负责在设备间传输文件，应用本身不实现云端同步服务或账号体系。

## 2. 核心决策

| 项目 | 设计约定 |
| --- | --- |
| 目标平台 | Windows（x64 / 实验性 x86）与 Linux（amd64 / arm64），无原生桌面 GUI |
| 技术栈 | Go 后端 + 嵌入的 React / TypeScript / shadcn/ui 网页，无运行时 Node.js 或远程资源依赖 |
| 条目结构 | 明文 `key` + `description` + 单层 `group`，加密 `value` 与独立加密附件；每条最多一个组 |
| AI 发现机制 | 先读取明文 `key`、`description`、`group` 判断相关性，再按 key 策略按需申请正文或附件 |
| 解锁与设备 | 单一主密码；每台设备可独立配置用户级登录自启动、系统凭据自动解锁及 90 天记住浏览器 |
| AI 权限 | 每个 key 的读取、修改分别配置三态策略：`allow`（无须授权）/ `ask`（需要授权）/ `deny`（拒绝） |
| 审批交互 | 优先在支持 form elicitation 的 harness 内确认；不支持时转至本地网页审批 |

## 3. 条目与分组模型

| 字段 | 用途 |
| --- | --- |
| `entry_id` | 稳定条目身份，创建时生成，重命名/删除/恢复沿用 |
| `key` | 唯一逻辑名称，明文且受 AAD 保护 |
| `description` | 明文用途说明，供 AI 优先检索与判断 |
| `group` | 可选单层分组（1–64 字符，不含首尾空白、控制字符、`/`、`\`；空串为未分组，保留“未分组”显示名） |
| `value` | 加密正文，支持纯文本、Markdown（禁用 HTML 与外链图片的安全预览）和 JSON |
| `attachments` | 零个或多个加密附件 |
| `read_policy` / `write_policy` | AI 读取与修改策略（新条目默认均为 `ask`） |

- **检索与编辑**：网页与 MCP 共用元信息检索和分组精确筛选；网页解锁后支持内存正文匹配，不持久化明文索引，也不向 MCP 开放正文搜索。
- **删除与重命名（格式 2+）**：仅限已认证网页。重命名生成新版本并保留正文、附件、权限与历史；删除追加带 `deleted: true` 的认证版本（回收站），不清理历史或安全擦除，回收站仍占用原 key。
- **单层分组（格式 3）**：成员关系仍由当前条目及回收站推导；独立空组及已观察到的组名另外保存在本机配置目录 `group-catalogs/`，按资料库身份与路径隔离，刷新和进程重启后保留。该本机目录不参与跨设备同步或资料库 ZIP 备份，不改变格式 3 的认证记录。支持批量移动与全组重命名/解除（单批上限 20 条 / 8 MiB）。AI 可读取和按组筛选，不得修改分组。

## 4. 权限与 MCP 流程

- **读写分离**：修改授权允许 AI 基于 `expected_revision` 提交完整替换，不包含读取旧 `value` 的权限；写入结果仅返回状态与新版本。
- **单次审批绑定**：批准绑定发起客户端、请求 ID、目标 key、操作范围、内容摘要与当前版本；超期（5 分钟）、版本变化、权限变化或资料库锁定时原批准失效。
- **统一状态管理**：网页与 MCP 共用后台 `access` 与 `vault` 服务；harness 确认与网页审批对应同一请求，仅可执行一次。

## 5. 架构与存储模型

```text
人类用户 ── 浏览器网页 ─────────────┐
                                  ▼
AI harness ── MCP (HTTP) ──▶ Go 本地后台服务
                                  │
                             资料库目录 (vault.json + records/)
                                  ↕ 外部同步工具
                           其他设备的资料库目录
```

- **后端模块**：`cmd/foliochest`（唯一入口）、`internal/app`（实例锁与服务生命周期）、`internal/server`（HTTP/MCP/会话/设备设置）、`internal/access`（策略与审批队列）、`internal/vault`（加解密、不可变批次、冲突与备份）、`internal/platform`（系统凭据、自启动、会话/电源锁屏监听、目录选择器）、`internal/fsutil`（限长读与原子替换）。
- **本机目录与资料库分离**：`vault.json` 与 `records/` 位于用户选择的同步目录；本机设备配置（`device.json`、`settings.json`、`location.json`、`clients.json`、`launcher.lock`）保存在用户配置目录（沿用 `keyfolio/` 以保持兼容），不参与同步。
- **不可变批次与冲突处理**：每次提交写入新的随机 `<batch-id>.json`，通过写临时文件 + fsync + 同目录改名发布，记录 `parents` 依赖。离线并发修改同一父版本会产生多分支冲突，保留全部候选版本供网页合并或恢复；不同 `entry_id` 的同名冲突会阻止写入并提示冲突。

## 6. 网页界面约束

- **当前试用配色**：白底，鸢尾紫主色 `#6941C6`、浅丁香选中背景 `#F1EBFC`、正文近黑 `#24212B`、次要文字 `#67616E`，侧栏近白 `#FBFAFC`。主色仅用于操作和选中状态，分组不大面积铺色，不使用渐变；样式 token 维护在 `web/src/styles/index.css`。
- **空组展示**：“显示空组”按钮本身显示开关状态，偏好保存在当前浏览器。关闭时隐藏空组，但本次新建的组临时显示；刷新或重新解锁后清除该例外。创建、重命名、移除空组只对已认证网页开放，保留名称校验与同源/CSRF 检查。底部回收站、设置、锁定、退出四个按钮同排。
- **标题层级**：桌面端不设独立顶栏，页面标题位于内容区；条目标题与编辑/历史操作同排。待审批入口放在侧栏品牌区；窄屏保留导航及审批入口。设置、授权请求保留各自内容标题，弹窗和分区标题不删除。
- **参考图布局**：侧栏采用无框分组与紧凑条目行，描述保留在条目属性中；设置采用下划线标签，设备配置行展示图标、说明、实际状态或未保存状态及开关，保留显式保存与密码确认。属性区压缩为 Key/分组/描述与权限两行，窄屏自动换行；正文编辑器随可用空间伸展，附件区提供文件选择与拖拽提示。
- **附件拖拽**：仅将文件加入当前可编辑草稿，与文件选择共用限额检查和异步会话检查；保存后才写入库。不接受文件夹；只读、加载或提交期间拒绝添加，拖动正文文字不触发附件处理。

- **单一正式入口**：`web/src/main.tsx` 构建后嵌入 Go 二进制，所有操作连接真实后端 API。
- **布局与交互**：双栏工具布局（左侧可折叠分组资料树 + 搜索，右侧纵向排列属性、正文、附件），按需弹窗处理创建/打开/恢复/历史/管理；仅在存在待审批请求时于顶栏显示审批提示入口。
- **安全约束**：严格 CSP（禁止 `unsafe-inline` 脚本与 `unsafe-eval`，Radix/CodeMirror 动态样式使用服务端每页随机 nonce）；会话变更或锁定时立即清除正文、草稿、密码输入和一次性接入凭据；异步请求与文件读取返回后复查当前会话与编辑代次。

## 7. 待演进方向

- Windows 真机安装/系统事件验收，以及正式发布前的独立安全审计。
- 不同 `entry_id` 同名冲突处理、历史清理、跨分支附件合并。
- 独立离线恢复 CLI、明文导出工具与完整的数据密钥轮换。
- 更多 MCP harness 的原生交互审批适配（如 `2026-07-28` 多轮审批）。
